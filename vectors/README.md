# Test vectors

One JSON file per suite. Generated by `sage-vectors gen` from the Go core and
verified with `sage-vectors check`; do not edit by hand.

## File format

```json
{
  "suite": "rfc9421",
  "spec_version": "1.0.0-draft.1",
  "generator": "sage-vectors 1.5.2",
  "description": "...",
  "vectors": [
    {
      "name": "request-ed25519",
      "mode": "deterministic",
      "description": "...",
      "input": { "...": "..." },
      "output": { "...": "..." }
    }
  ]
}
```

- `mode`: `deterministic` (recompute `output` from `input` and compare) or
  `verify` (run the verification path on `output`; the generating side drew
  randomness, so bytes differ between generators but must always verify).
- Binary values are lower-case hex without a prefix. HTTP header values,
  DIDs, labels and JSON documents are plain strings.
- Every private key is derived from a label: `seed = SHA-256(label)`. Ed25519
  uses the 32 bytes as the RFC 8032 seed; secp256k1 and X25519 use them as the
  scalar; P-256 reduces them modulo the group order. The labels are in the
  inputs so vectors can be reproduced without any other secret.

## Suites

| Suite | Vectors | Covers |
|---|---|---|
| `crypto` | 4 | Ed25519, secp256k1 (Keccak-256, RFC 6979, `r||s||v`), P-256 (SHA-256, raw `r||s`, low-S), key identifier |
| `jcs` | 4 | RFC 8785 Appendix A and section 3.2.3 samples, an agent-card-shaped object, number formatting |
| `rfc9421` | 4 | Signed request per algorithm (signature base, `Signature-Input`, `Signature`, `Content-Digest`), response signature bound with `;req` |
| `hpke` | 6 | `info` and export-context strings, X25519 E2E secret, combiner, traffic keys, ack tag, exporter round trip |
| `session` | 3 | Seed and id derivation, records at seq 0 and after key rotation, directional keys with AAD |
| `did` | 5 | Grammar (accepted and rejected forms), chain aliases, key proof of possession (Ed25519, secp256k1), A2A card proof |

## Regenerating

From a checkout of the Go core next to this repository:

```bash
make vectors            # writes ../sage-spec/vectors
make vectors-check      # verifies the Go core against ../sage-spec/vectors
```

`gen` keeps verify-mode outputs that still verify, so a regeneration only
changes files when the protocol changed.
