# 7. A2A agent card

Vectors: `vectors/did.json` (`a2a-card-proof-ed25519`), `vectors/jcs.json`
(`agent-card-like`). Go sources: `pkg/agent/did/a2a.go`, `a2a_proof.go`,
`types_v4.go`.

## 1. Card

The card is the registry record of `06-did-sage.md` §3 projected into the
A2A / DID-core shape:

| Member | Content |
|---|---|
| `@context` | `["https://www.w3.org/ns/did/v1", "https://w3id.org/security/suites/ed25519-2020/v1", "https://w3id.org/security/suites/secp256k1-2019/v1"]` |
| `id` | the DID |
| `type` | `["Agent", "AIAgent"]` |
| `name`, `description` | strings |
| `publicKey[]` | one entry per registered key, in registry order |
| `service[]` | `{type, uri}` endpoints |
| `capabilities` | array of capability names (optional) |
| `created`, `updated` | RFC 3339 timestamps |

Each `publicKey` entry:

| Member | Content |
|---|---|
| `id` | `<DID>#key-<n>`, `n` starting at 1 in registry order |
| `type` | `Ed25519VerificationKey2020`, `EcdsaSecp256k1VerificationKey2019` or `X25519KeyAgreementKey2019` |
| `controller` | the DID |
| `publicKeyBase58` | base58 of the raw key bytes |
| `publicKeyHex` | hex of the same bytes |

Both encodings MUST decode to the same bytes; verifiers MAY reject a card
where they differ. No multibase encoding is used.

## 2. Proof

```json
"proof": {
  "type": "Ed25519Signature2020" | "EcdsaSecp256k1Signature2019",
  "created": "<RFC 3339>",
  "verificationMethod": "<DID>#key-<n>",
  "proofPurpose": "assertionMethod",
  "proofValue": "<base58 signature>"
}
```

The signature is computed over the JCS canonical form (`02-jcs.md`) of the
card **without** the `proof` member, using the key named by
`verificationMethod`: Ed25519 over the canonical bytes, or secp256k1 with
the Keccak convention of `01-crypto.md`. `proofValue` is base58 of the raw
signature (64 or 65 bytes).

## 3. Verification

1. Parse the card; keep the received JSON.
2. `verificationMethod` MUST start with `<id>#`.
3. Find the `publicKey` entry with that `id`; its `type` MUST match the
   proof `type`.
4. Delete `proof` from the received JSON, canonicalise, and verify the
   signature with the key's bytes.
5. When a resolver is available, the key MUST also appear, verified, in the
   on-chain record of `id`.

The vector is verify-only because `proof.created` is the signing time.
